## 第一期：答题型付费测评（本框架的基准路线）

- 标题：《用AI打造价值10w的小生意》
- 时长：8分17秒；页面显示 10-10、广东；可见 4345 赞、7622 收藏、382 评论
- 原笔记短链：https://xhslink.cn/o/4mqLtY5lrVp
- 核心产品：小型付费答题测评
  - AI 生成题目 / 计分 / 结果（题目、文案、代码均为原产品的，**本项目只借鉴思路和流程，做原创内容，不照搬**）

- 技术栈：

  - 后端：Supabase（核心是数据库，管密钥状态、用户、结果数据；另有账号、存储、接口）

**本框架按第一期搭建**：密钥入口 → 答题 → 计分 → 结果页 → 重测（需新密钥），内容（主题、题目、结果）全部抽到 `frontend/content.json`，后面换主题不用改代码。

## Supabase 与 Cloudflare 的区别（第一期 vs 第二期）

一句话：**它们不是同类产品，一个是管数据的后端，一个是跑代码的中间层。**

- **Supabase（第一期）**：后端即服务，核心是数据库，适合存东西——密钥有没有用过、用了几次、属于哪一批、什么时候生成，用户和结果数据也适合放这里。
- **Cloudflare Workers（第二期）**：无服务器计算中间层，在服务器端保管模型密钥、转发调用，适合“前端不能直接调模型”的场景。
- GitHub Pages 只能放静态页，密钥写进前端等于公开。
- 两者可配合使用：Supabase 管密钥和数据，Workers 管模型调用。

## 始终守住的边界（两期都适用）

- 不能替用户开小红书店铺、实名认证、绑收款账号、备案 / 营业执照；这些必须用户本人完成
- 未接通店铺 / 支付并经授权前，不能替用户收款或自动发货；没接通之前，密钥只能先手动发
- 纯前端密钥可被绕过或分享，严格一次性校验需后端数据库
- 不保证销量或 10 万收入；“较冷门”只是公开检索推断，上线前需在小红书 App 内复核关键词与虚拟产品上架规则
- 趣味测评只讲一般联系，不做睡眠 / 心理诊断，不承诺助眠等疗效（主题确定后按主题再定具体边界）
