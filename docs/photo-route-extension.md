# 照片路线预留接口（第二期视频）

> 当前框架只做第一期答题路线。**现在不做照片上传、不接模型、不存照片。**下面是以后如果要做第二期路线时，怎么在不重写密钥系统和结果页的前提下接进去。
> 视频要点与限制见 `docs/video-notes.md`。

## 设计原则

1. **密钥先行**：上传照片前必须先过同一套密钥校验（`validate-key`），密钥用完即作废；不要出现“默认链接可被转发、不用密钥就能测”的口子（第二期抽查画面里未演示密钥交付，作者评论称默认链接理论上可被转发）。
2. **模型密钥绝不进前端**：阿里云百炼的 API key 只放在 Cloudflare Workers（或 Supabase Edge Function）里，前端只调自己的后端端点。
3. **不存照片**：照片只做一次性分析，不写入存储、不留档；分析完即丢弃。是否保存须由用户另外决定并在页面上明示。
4. **不打颜值分**：方向按第二期改为“陌生人眼中的第一印象”这类更安全、更易分享的解读，不做外貌打分。

## 预留的接入点

- 前端：在 `config.js` 里加 `mode: 'quiz'`（默认）或 `'photo'`；`index.html` 里预留一个 `#photo` 区块（目前未启用），启用时替换答题区块，流程变为：密钥入口 → 上传一张正面照 → 后端分析 → 结果页（结果页、分享卡、重测逻辑与答题路线共用）。
- 后端：新增一个 Worker / Edge Function `analyze-photo`，职责只有三件事：校验 sessionToken 是否有效且未用过 → 调阿里云百炼 qwen3-vl-plus → 把模型返回的结果映射到 `content.json` 里的 results 结构（只返回结果 id + 解读文案，不把原始模型输出直接透传给前端）。
- 内容：照片路线的结果也要先写进 `content.json` 的 `results` 里（标题、正文、learn、try、shareText），模型只负责“选哪个结果 + 补一句个性化解读”，不负责现编结果文案——否则结果质量不可控，也容易出现不合适的表述。

## 开工前置条件（用户本人完成，缺一不可）

- 阿里云百炼实名 / 试用开通、Cloudflare 账号准备
- 定好规则并写进页面：不存照片、只做第一印象类解读、不打分外貌
- 另行确认照片上传的隐私提示与同意文案；未成年人照片、他人照片一律不接受
