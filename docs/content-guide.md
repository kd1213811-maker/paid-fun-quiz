# 换主题指南：只改 content.json

> 正式主题、题目、结果确定后，按下面格式改 `frontend/content.json` 即可，不用改 `app.js`、`index.html`、后端代码。
> 改完后在本地跑一遍：密钥进入 → 每道题都能选 → 返回上一题能改 → 结果页的标题、正文、分享卡都对得上。

## 文件结构

```json
{
  "meta": {
    "title": "测评标题",
    "subtitle": "一句话说明测什么、不测什么",
    "sharePrefix": "我刚测完一个趣味小测评，",
    "disclaimer": "仅供娱乐，不构成医疗或心理评估。",
    "version": "1.0.0"
  },
  "scoring": {
    "mode": "count",
    "tieBreak": "priorityQuestion",
    "priorityQuestionIndex": 4,
    "note": "平局时先看优先题指向的结果，再按 results 顺序取先"
  },
  "dimensions": [
    { "id": "d1", "label": "维度一名" }
  ],
  "questions": [
    {
      "id": "q1",
      "text": "题目",
      "options": [
        { "text": "选项", "scores": { "A": 1, "d1": 1 } }
      ]
    }
  ],
  "results": [
    {
      "id": "A",
      "title": "结果标题",
      "body": "结果正文：先给新信息，再讲为什么",
      "learn": "学到的一点",
      "try": "可以试试的一个小改变",
      "shareText": "我是××型，你呢？"
    }
  ]
}
```

## 规则

- **计分**：每个选项的 `scores` 里，键是结果 id 或维度 id，值是加分（一般为 1）。一个选项可以同时给多个结果 / 维度加分，也可以只给维度加分、不给任何结果加分（适合“只影响画像、不决定主结果”的题）。
- **胜出**：所有结果里总分最高者胜出；`dimensions` 只做画像展示，不决定胜出。
- **平局**：`tieBreak: "priorityQuestion"` 时，先看 `priorityQuestionIndex` 指定的那道题（从 0 开始数，4 就是第 5 题）指向的并列结果；如果那题也不在并列里，再按 `results` 在本文件中的顺序取先。**不要**用“按出现顺序取先”当唯一规则——如果某个结果的选项总在 A 位，会系统性偏向它；正式版搭建时要复核各结果在 A–D 各位置的分布是否大致均匀。
- **题目数量**：框架不限制题数，但建议一次测评控制在 5–12 题；题太多会让“2 分钟测完、马上分享”的轻量感消失。
- **结果数量**：建议 4–6 种；每种都要有 `learn`（新信息）和 `try`（今晚 / 今天就能试的具体小改变），不要只剩称号和金句。
- **免责声明**：`meta.disclaimer` 会显示在结果页；涉及睡眠、健康、心理等主题时，必须保留“仅供娱乐，不构成医疗或心理评估”，且不在结果里打分、诊断或承诺疗效。
- **不要写进 content.json 的东西**：密钥、后端地址、价格、店铺链接——这些放在 `config.js` 或店铺商品页里，不要和题目内容混在一起。
